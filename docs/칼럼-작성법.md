# 칼럼 작성법

칼럼은 `columns/` 폴더의 markdown 파일 하나가 글 하나다. 글 중간에 **근거 상자**를 끼워 넣으면, 사이트를 만들 때 실제 데이터로 계산한 숫자가 들어간다. 글에 적는 숫자를 손으로 옮기지 않아도 되고, 데이터를 갱신하고 다시 빌드하면 상자도 따라 바뀐다.

## 작업실에서 쓰기
작업실(비공개 페이지)의 **칼럼 → 새 칼럼 쓰기**에서 쓴다. 왼쪽에 제목·날짜·종류·관련 팀·요약과 본문, 오른쪽에 실제 데이터로 계산한 미리 보기가 나온다. 입력이 멈추고 3초 뒤 자동 저장되고, 원고는 그 페이지의 저장소에 소유자만 읽고 쓸 수 있게 남는다. "견본 불러오기"는 경기 분석 견본(`columns/_template-analysis.md`)을 본문에 넣고, "근거 상자 넣기"는 상자 줄을 커서 위치에 넣는다. 상자 안 챔피언·팀은 한글 이름도 된다(예: `blue.mid=오리아나`, `team="젠지"`). 다 쓴 원고는 Claude에게 가져오라고 하면 `columns/날짜-주제.md`로 옮긴다. ".md 내려받기"로 파일을 직접 받을 수도 있다.

## 경기 분석 글의 구성 (견본)
한 줄 결론 → 경기 정보 → 밴픽: 양 팀은 무엇을 노렸나 → 게임 플랜: 각 조합의 이기는 방법 → 분기점(시간 순 2~3장면, `###` 소제목) → 데이터로 확인: 평소에도 그런가 → 정리와 다음 관전 포인트. 데이터는 마지막 확인 단계에서만 쓰고, 결론은 장면 해석으로 낸다.

## 파일 모양
```
---
title: 피어리스 후반 세트, 같은 미드가 또 나온 이유
date: 2026-11-05
kick: 칼럼
lede: 목록에 보일 한두 문장
teams: T1, Gen.G
---
본문 문단. 빈 줄로 문단을 나눈다.

## 소제목

@search blue.mid=Azir red.mid=Orianna sets=late

문단 사이에 상자를 마음대로 넣는다.

@series pick=longest set=4
```
머리말의 `title`과 `date`(2026-11-05 모양)는 필수다. 선택 항목:
- `teams`: 관련된 팀의 영문 이름(데이터와 같은 표기)을 쉼표로. 작업실의 팀 페이지에 글이 나온다.
- `kind`: `column`(기본, 칼럼) 또는 `note`(분석 노트: 가설과 확인 결과를 남기는 글).
- `draft`: `true`면 초안. 작업실에서는 보이지만 공개 사이트에는 실리지 않는다.

파일 이름은 자유지만 `날짜-주제.md`를 권한다. `_`로 시작하는 파일(견본)은 공개 사이트에 실리지 않는다.
소제목(`## `, 작은 소제목 `### `)과 상자(`@`) 줄은 앞뒤에 빈 줄이 없어도 따로 읽는다.

## 근거 상자
| 상자 | 쓰는 법 | 보여 주는 것 |
| --- | --- | --- |
| `@search` | `team="Gen.G" blue.mid=Orianna` | 경기 수, 전적, 승률, 95% 범위, 15분 평균 골드 차이. `team`을 쓰면 그 팀이 고른 경기만, 없으면 그 챔피언을 고른 모든 팀. `games=3`이면 경기 목록을 한 줄씩 3개까지 |
| `@series` | `pick=longest set=4` | 시리즈의 세트별 소진 챔피언, 포지션별 인기 상위 챔피언이 몇 명 남았는지 |
| `@game` | `nth=40` 또는 `id=게임ID` | 경기 하나의 밴픽 카드 |
| `@draft` | `teams="젠지,BLG" set=2`, 날짜가 필요하면 `date=2026-11-14`, 그 시점까지만 보려면 `upto=6`(밴·픽 선택 순서 1~20), 강조는 `hl="카시오페아,노틸러스"` | 한 세트 밴픽 보드: 페이즈별 밴·픽, 전체 픽 순서 번호, 이전 세트 소진 챔피언, 승리 팀(upto가 있으면 숨김). 팀 안의 순서는 데이터 그대로, 두 팀 사이 순서는 표준 드래프트 규칙으로 맞춘다 |
| `@team` | `name="Gen.G"` 또는 `name="Gen.G" show=gd15,barS` | 맨 위에 리그 평균과 차이가 큰 지표를 큰 숫자 카드로(최대 4개), 아래에 초반·경기 전체 표(순위 \| 지표 \| 팀 값 \| 리그 평균). 차이가 클 때만 더 나은 쪽 값에 색. 8경기 미만이면 "표본 부족"으로 흐리게. `show`를 쓰면 고른 지표만 카드로 보여 준다 |
| `@form` | `team="Gen.G" n=10 until=2026-11-14` | 최근 n경기(3~30)를 한 줄씩: 날짜, 상대, 15분 골드 차이 가로 막대, 승패 |
| `@flow` | `team="Gen.G"` (최근 경기), `team="Gen.G" last=3`, 또는 `id=게임ID team="Gen.G"` | 그 팀 기준 경기 하나: 양 팀 챔피언, 시간대별 골드 차이(눈금 있음), 10·15분 차이, 최종 수치, 먼저 가져간 쪽. 지정한 팀이 뛰지 않은 경기면 오류 |

값에 빈칸이 있으면 큰따옴표로 감싼다: `name="Hanwha Life Esports"`. 게임 ID는 작업실의 경기 상세에서 확인한다.

`@search`의 인자
- `blue.<포지션>=챔피언`, `red.<포지션>=챔피언`: 포지션은 `top jng mid bot sup`, 챔피언은 영문 이름(데이터와 같은 표기, 예: `Kai'Sa`, `Nunu & Willump`). 한 팀에만 쓰면 어느 진영이든 찾고, 양쪽에 쓰면 진영이 바뀐 경기도 찾는다.
- `sets=all|early|late`: late가 4~5세트다.
- `patch=all|latest|last3`, `leagues=LCK,LPL`, `pos=any|exact`(같은 포지션만).

`@series`의 `pick`은 `longest`(가장 긴 시리즈 중 가장 최근) 또는 `latest`, `set`은 몇 세트 후 상태를 보여 줄지다.

## 상자 모양
모든 상자는 같은 틀이다: 제목(무엇을 셌는지) → 숫자·그래프 → 출처 한 줄. 문장으로 해석하지 않는다. 해석은 상자 앞뒤 본문에 쓴다.

팀 지표는 시간 기준으로 두 묶음이다: **초반**(15분 전후까지: 15분 골드·경험치·CS 차이, 첫 킬, 첫 포탑, 포탑 방패, 유충, 전령)과 **경기 전체**(분당 골드·CS·피해량·시야·와드 제거, 킬·데스, 용·바론 획득 비율, 15분 우위 시 승률). 이 묶음은 이 사이트가 정한 것이고 LCK나 업계의 공인 분류가 아니다. 쓸 때 주의: 경기 전체 지표 대부분은 승패를 크게 반영하므로(이긴 팀이 용·바론·킬을 더 가져간다) "이 팀이 강하다"는 확인일 뿐, 이유로 쓰지 않는다. 색은 한 가지 뜻만 갖는다: 리그 평균과의 차이가 리그 최고–최저 폭의 4분의 1 이상이면 더 나은 쪽에 색(초록 = 팀이 앞섬, 빨강 = 평균이 앞섬). 순위 배지는 색 없이 두고 1위만 테두리로 표시한다(순위 색과 차이 색이 다른 말을 하지 않게). 낮을수록 좋은 지표(경기당 데스)는 방향을 뒤집어 계산한다.

`show`에 쓸 수 있는 지표: `gd15`(15분 골드 차이) `xpd15`(15분 경험치 차이) `csd15`(15분 CS 차이) `fb`(첫 킬) `ft`(첫 포탑) `plt`(포탑 방패) `grub`(공허 유충) `her`(전령) `gpm`(분당 골드) `cspm`(분당 CS) `dpm`(분당 피해량) `vspm`(분당 시야 점수) `wcpm`(분당 와드 제거) `k`(경기당 킬) `d`(경기당 데스) `drgS`(용 획득 비율) `barS`(바론 획득 비율) `ahead`(15분 우위 시 승률).

참고한 사이트: dpm.lol(팀 값과 리그 평균 두 열, 더 나은 쪽 강조, 순위 배지), Opta Analyst(큰 숫자 카드와 서수), Basketball Reference(값 옆 순위, 1위 강조), Baseball Savant(낮을수록 좋은 지표 방향 보정, 표본 부족 표시).

## 스카우팅 리포트 형식
`columns/_template-scouting.md`가 견본이다. 한 줄 요약 → 팀 지표(`@team`) → 최근 흐름(`@form`) → 대표 경기(`@flow`) → 밴픽 포인트(`@search`) → 대응 제안 순서다. 상자는 근거만 보여 주고, 해석과 결론은 글로 쓴다.

## 빌드와 확인
```bash
python -m src.build_site --out site --with-app                        # 작업실에서 글 미리 보기
python -m http.server 8000 --bind 127.0.0.1 --directory site          # http://127.0.0.1:8000/#columns
python -m src.build_public --out public                               # 공개 사이트 (초안 제외)
python -m src.build_public --drafts --out public_preview              # 초안까지 넣어 미리 보기
```
문법이 틀리면 빌드가 멈추고 어느 파일 몇 번째 문단인지 알려 준다. 예: `2026-11-05-azir 3번째 문단: 알 수 없는 포지션 'middle'`.

공개 사이트의 상자는 빌드할 때 계산된 값이다. 데이터를 갱신하면 공개 사이트를 다시 빌드해야 숫자가 바뀐다. 공개 사이트에는 작업실로 가는 버튼("검색기에서 열기" 등)이 없다.
