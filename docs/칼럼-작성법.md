# 칼럼 작성법

칼럼은 `columns/` 폴더의 markdown 파일 하나가 글 하나다. 글 중간에 **근거 상자**를 끼워 넣으면, 사이트가 열릴 때 실제 데이터를 검색해서 숫자와 경기 카드를 만든다. 글에 적는 숫자를 손으로 옮기지 않아도 되고, 데이터가 바뀌면 상자도 따라 바뀐다.

## 파일 모양
```
---
title: 피어리스 후반 세트, 같은 미드가 또 나온 이유
date: 2026-11-05
kick: 칼럼
lede: 목록에 보일 한두 문장
teams: T1, Gen.G
---
본문 문단. 빈 줄로 문단을 나눈다.

## 소제목

@search blue.mid=Azir red.mid=Orianna sets=late

문단 사이에 상자를 마음대로 넣는다.

@series pick=longest set=4
```
머리말의 `title`과 `date`(2026-11-05 모양)는 필수다. 선택 항목:
- `teams`: 관련된 팀의 영문 이름(데이터와 같은 표기)을 쉼표로. 작업실의 팀 페이지에 글이 나온다.
- `kind`: `column`(기본, 칼럼) 또는 `note`(분석 노트: 가설과 확인 결과를 남기는 글).
- `draft`: `true`면 초안. 작업실에서는 보이지만 공개 사이트에는 실리지 않는다.

파일 이름은 자유지만 `날짜-주제.md`를 권한다. `_`로 시작하는 파일(견본)은 공개 사이트에 실리지 않는다.
소제목(`## `)과 상자(`@`) 줄은 앞뒤에 빈 줄이 없어도 따로 읽는다.

## 근거 상자
| 상자 | 쓰는 법 | 보여 주는 것 |
| --- | --- | --- |
| `@search` | `blue.mid=Azir red.mid=Orianna` | 조건에 맞는 경기 수, 승률, 골드차, 경기 카드 3개, "검색기에서 열기" 버튼 |
| `@series` | `pick=longest set=4` | 시리즈의 세트별 소진 챔피언, 인기 픽 소진, "시리즈 복기 열기" 버튼 |
| `@game` | `nth=40` 또는 `id=게임ID` | 경기 하나의 밴픽 카드 |
| `@team` | `name="Gen.G"` | 팀 지표를 같은 리그 안 순위·평균과 비교, 레이더 |
| `@form` | `team="Gen.G" n=10 until=2026-11-14` | 최근 n경기(3~30, until 날짜까지)의 15분 골드 차이와 승패 |
| `@flow` | `id=게임ID team="Gen.G"` (또는 `nth=40`) | 경기 하나의 시간대별 골드 차이, 10·15분 골드·경험치·CS 차이, 15분 킬, 먼저 가져간 오브젝트, 최종 킬·포탑·용·바론·억제기 |

값에 빈칸이 있으면 큰따옴표로 감싼다: `name="Hanwha Life Esports"`. 게임 ID는 작업실의 경기 상세에서 확인한다.

`@search`의 인자
- `blue.<포지션>=챔피언`, `red.<포지션>=챔피언`: 포지션은 `top jng mid bot sup`, 챔피언은 영문 이름(데이터와 같은 표기, 예: `Kai'Sa`, `Nunu & Willump`). 한 팀에만 쓰면 어느 진영이든 찾고, 양쪽에 쓰면 진영이 바뀐 경기도 찾는다.
- `sets=all|early|late`: late가 4~5세트다.
- `patch=all|latest|last3`, `leagues=LCK,LPL`, `pos=any|exact`(같은 포지션만).

`@series`의 `pick`은 `longest`(가장 긴 시리즈 중 가장 최근) 또는 `latest`, `set`은 몇 세트 후 상태를 보여 줄지다.

## 상자 모양
모든 상자는 같은 틀이다. 맨 위에 조건 태그, 그 아래 **결론 한 문장**(자동으로 만든다. 예: "정글 바이 + 미드 오리아나를 고른 팀이 45경기에서 56% 이겼어요"), 핵심 숫자, 근거, 맨 아래 출처·기준 한 줄. 경기 카드는 하나만 보이고 나머지는 "더 보기"로 접힌다. 결론 문장은 데이터가 보여 주는 사실만 말하므로, 해석은 상자 앞뒤 본문에 쓴다.

## 스카우팅 리포트 형식
`columns/_template-scouting.md`가 견본이다. 한 줄 요약 → 팀 지표(`@team`) → 최근 흐름(`@form`) → 대표 경기(`@flow`) → 밴픽 포인트(`@search`) → 대응 제안 순서다. 상자는 근거만 보여 주고, 해석과 결론은 글로 쓴다.

## 빌드와 확인
```bash
python -m src.build_site --out site --with-app                        # 작업실에서 글 미리 보기
python -m http.server 8000 --bind 127.0.0.1 --directory site          # http://127.0.0.1:8000/#columns
python -m src.build_public --out public                               # 공개 사이트 (초안 제외)
python -m src.build_public --drafts --out public_preview              # 초안까지 넣어 미리 보기
```
문법이 틀리면 빌드가 멈추고 어느 파일 몇 번째 문단인지 알려 준다. 예: `2026-11-05-azir 3번째 문단: 알 수 없는 포지션 'middle'`.

공개 사이트의 상자는 빌드할 때 계산된 값이다. 데이터를 갱신하면 공개 사이트를 다시 빌드해야 숫자가 바뀐다. 공개 사이트에는 작업실로 가는 버튼("검색기에서 열기" 등)이 없다.
