# 기술 스택 결정

2026-11-19. 결론: **서버 없는 정적 사이트(HTML/JS) + Python 전처리.** 데이터 이용 조건을 확인하기 전에는 공개하지 않는다.

## 요구 사항
- 일반 사용자(중계 팬, 칼럼 독자)가 폰으로 쓴다. 클릭형 밴픽 보드, 카드, 상세 창이 필요하다.
- 경기가 끝난 뒤의 복기가 중심이라 실시간 갱신은 필요 없다. 데이터는 CSV를 받을 때만 바뀐다.
- 혼자 운영한다. 서버 관리와 비용이 거의 없어야 한다.
- 포트폴리오다: 수집·정제·검색·화면을 직접 만든 흔적이 보여야 한다.

## 측정한 사실 (실제 2026 데이터, 9,940경기 · 4,523시리즈)
| 항목 | 값 |
| --- | --- |
| 처음 열 때 받는 데이터 | 약 0.9MB (gzip, 아이콘 제외) / 1.35MB (아이콘 포함) |
| 데이터 로딩 후 화면이 뜨기까지 | 약 1.5초 |
| 검색(조합 찾기) | 약 0.2초 |
| 경기 상세 열기 | 약 15ms |
| 서버가 필요한 계산 | 없음. 모두 브라우저에서 계산한다 |

## 후보 비교
| | Streamlit | 정적 사이트 (선택) | Next.js + DB/API |
| --- | --- | --- | --- |
| 클릭형 보드, 카드, 상세 창 | 어렵다. 입력할 때마다 화면 전체가 다시 그려진다 | 자유롭다 | 자유롭다 |
| 모바일, 공유 링크 | 약하다 | 좋다 (`#column-1` 같은 주소) | 좋다 |
| 서버·비용 | 서버가 계속 떠 있어야 한다 | 파일만 올리면 된다 (무료 호스팅 가능) | 서버나 DB가 필요하다 |
| 운영 부담 | 중간 | 낮다 | 높다 |
| 이 규모(1만 경기)에 맞나 | 맞다 | 맞다 | 과하다 |

## 구조
```
data/raw/*.csv ──python -m src.prepare──▶ data/games.parquet ──python -m src.build_site──▶ site/
                                                          (champs.json, games.json, columns.json, icons/)
columns/*.md ─────────────────────────────────────────────┘                    + mockup/index.html, app.js
```
- 검색, 쌍둥이, 피어리스 복기는 모두 `mockup/app.js`가 브라우저에서 계산한다. 같은 로직의 파이썬 구현(`src/search.py`)과 테스트는 설계 기준과 비교용으로 남긴다.
- 갱신: 새 CSV를 `data/raw/`에 넣고 위 두 명령을 다시 실행해 `site/`를 올린다.
- 화면 코드는 지금 일반 JavaScript 한 파일(약 800줄)이다. 3천 줄을 넘기거나 협업이 생기면 TypeScript + Vite로 옮긴다. 지금 옮길 이유는 없다.
- 기존 Streamlit 앱(`app.py`)은 공개하지 않고, 내가 로컬에서 쓰는 분석용으로만 남긴다.

## 공개 전에 확인할 것
사이트를 공개하면 `games.json`을 누구나 내려받을 수 있다. 즉 **Oracle's Elixir 데이터를 가공해 재배포하는 것**이다.

**Oracle's Elixir 다운로드 페이지(사용자가 캡처로 확인, 2026-11-20)가 말하는 것**
- 데이터는 Tim Sevenhuysen이 수집해 공개한 것이고, **무료로 "분석가, 해설자 및 팬들이 사용할 수 있도록" 제공**된다.
- "게임 통계는 라이엇 게임즈의 자산이며, 해당 데이터의 사용은 **라이엇 게임즈의 약관 및 정책을 준수**해야 한다."
- 데이터 파일은 **하루에 한 번** 업데이트된다. 파일은 Google Drive로 받는다.
- 하단에 "라이엇 게임즈의 공식적인 승인을 받지 않았으며…"라는 면책 문구가 있다. 일부 콘텐츠는 Leaguepedia의 CC-BY-SA 3.0이다(우리는 Leaguepedia 내용을 쓰지 않는다).
- **이 페이지에는 재배포(가공한 데이터를 다시 공개하는 것)에 대한 명시적 문구가 보이지 않는다.** 허용하는지 금지하는지 알 수 없다.

**라이엇 약관에서 읽은 것** (2026-11-20에 직접 읽음: Legal Jibber Jabber는 2018년 8월 개정, 개발자 포털 일반 정책은 2025년 5월 29일 개정)
- **무료 팬 프로젝트로는 허용된다.** 비상업이 원칙이고 예외는 세 가지다. ① 개인이 사이트에 다는 "적절한 광고"의 수동적 수익, ② 방송 후원, ③ 라이엇이 그 프로젝트에 발급한 유효한 API 키로 API 약관을 지키는 상업 프로젝트.
- **금지**: 후원 모집(크라우드펀딩), 사업체·법인이 낀 프로젝트, 유료 구독·페이월(예외 ③ 없이). 라이엇은 언제든 프로젝트를 중단시킬 수 있다고 밝힌다.
- 라이엇 로고·상표 사용 금지. 도메인·SNS 계정 이름에 상표나 챔피언 이름 사용 금지. **상표나 IP 관련 이름을 키워드·검색 태그로 쓰는 것도 금지**라서, 본문에 챔피언 이름을 쓰는 것과 별개로 메타 키워드·해시태그·광고 키워드에는 넣지 않는다.
- 앱스토어·구글 플레이 앱은 금지(웹사이트는 가능).
- 독창성: "경기 영상·e스포츠 경기에 가벼운 코멘트만 붙인 것"은 안 된다. 원본 분석을 더하는 서비스라 해당하지 않는다.
- **필수 고지문**을 사이트에서 눈에 띄게 보여 줘야 한다: Legal Jibber Jabber의 고지문과 개발자 포털의 면책 문구(둘 다 영어 원문 그대로). 목업 하단에 이미 넣었다.
- 개발자 정책: Data Dragon은 개발·홍보에 쓸 수 있는 에셋으로 명시돼 있다. 한편 "모든 제품은 개발자 포털에 등록하고 검수받아야 한다"는 문장이 있어, **Data Dragon만 쓰는 사이트에도 등록이 필요한지는 불분명하다.** 등록하는 쪽이 안전하다.
- 광고 이외의 수익화(후원, 구독)는 **등록 + 승인(또는 Acknowledged) 상태**가 필요하고, 무료로 쓸 수 있는 층이 있어야 하며, 유료라면 콘텐츠가 "변형적(새로운 정보·시각·통찰을 더한 것)"이어야 한다.
- 솔로랭크 연습 기록처럼 Riot API를 쓰는 기능은 등록과 프로덕션 키가 전제이고, "공개된 정보로 식별될 수 없는 플레이어를 익명 해제하는 제품"은 금지된다.

**해야 할 일**
1. 개발자 포털에 제품 등록을 검토한다. 수익화와 솔랭 기능의 전제 조건이기도 하다.
2. 출처(Oracle's Elixir, Tim Sevenhuysen)와 라이엇 고지문을 사이트에 넣는다(목업에 반영됨). 서비스 이름과 도메인에 라이엇 상표·챔피언 이름을 쓰지 않는다.
3. 가공한 데이터를 다시 공개해도 되는지는 Oracle's Elixir 페이지의 "문의"로 짧게 묻는다. 라이엇 약관상 "무료 팬 프로젝트"라는 틀 안에서는 가능해 보이지만, 데이터 제공자의 의사는 별개다.
4. 허용이 불분명하면: 선수 이름·시간대별 골드차 같은 항목을 빼고 밴픽 중심의 최소 데이터만 올리는 방안, 또는 공개하지 않고 칼럼에 캡처 이미지로만 싣는 방안을 쓴다.

확인 전까지는 `mockup/`에 **가짜 데이터만** 두고, 실제 데이터로 만든 `site/`는 저장소에 올리지 않는다(`.gitignore`).

## 로컬에서 확인하기
```bash
python -m src.build_site --out site --with-app
python -m http.server 8000 --bind 127.0.0.1 --directory site
```
`file://`로 열면 브라우저가 데이터 파일 읽기를 막으므로 위처럼 로컬 서버가 필요하다. 로컬 주소(127.0.0.1)에만 연결해 외부에서는 접근되지 않는다.
